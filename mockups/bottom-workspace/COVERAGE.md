# 기존 기능과 목업 대응표

Authon의 기존 사용자 화면 16개 영역에 신규 아티스트·부킹·일정·준비 업무 4개 영역을 추가한 검토용 목업입니다. 신규 4개 영역은 상용화 제안을 구현한 독립 목업이며 현재 제품에 배포된 기능이 아닙니다. 모든 영역은 상단 **기능 목록**에서 열 수 있습니다. 각 역할의 실제 메뉴에서도 해당 역할에 허용된 경로로 접근합니다. 기능 목록의 자동 역할 전환은 목업 검토 도구입니다.

## 기능 대응 재검토

기존 제품의 페이지와 관리자 작업 메뉴, 등록·도어·계정·링크·행사·통계 처리 화면을 대조했습니다. **16개 영역의 대표 업무 흐름은 존재하지만, 모든 세부 기능이 동일하게 구현된 상태는 아닙니다.** 아래의 ‘목업 구현’은 로컬 샘플 흐름을 의미합니다.

| 확인된 차이 | 기존 제품 | 현재 목업 |
| --- | --- | --- |
| 관리자 숫자 단축키 | 입력·모달 상태를 제외하고 숫자로 주요 작업 이동 | 클릭·Tab·Enter와 전체 메뉴를 사용하며 숫자 단축키는 미구현 |
| 링크 생성 날짜 | 날짜를 직접 선택하고 일반 명단 또는 선택한 행사에 연결 | 미리 생성된 운영 행사를 선택하며 날짜는 읽기 전용 |
| 통계 기간 URL | 월·분기·연과 기준 날짜를 URL에 반영하고 뒤로가기/새로고침으로 복원 | 화면 경로만 URL에 반영하며 기간 선택은 화면 내부 상태 |
| 조회 갱신 | 목록별 새로고침, 자동 갱신, 최신 응답·캐시 조정 | 한 탭 메모리의 변경 반영과 검토 상태 선택을 사용하며 실제 조회·자동 재연결은 모의 처리 |

외부 링크의 담당자 선택은 제품의 검색형 combobox를 목업의 select/datalist로 단순화했습니다. 외부 담당자의 독립 identity, 계정·토큰·수신 확인, 브라우저를 다시 연 뒤의 RSVP 복구와 오프라인 영속 저장도 실제 서비스와 동일한 구현이 아닙니다. 로그인·초대·재설정·승인·동기화 화면을 검토할 수 있다는 뜻이며, 실제 인증·메일·다른 기기 연결을 보장하지 않습니다.

`app/api/internal/sync-guest` 같은 서버 연동과 운영 API·D1·KV·세션 검증은 이 UI 목업에 연결하지 않습니다. 이벤트 수정 API처럼 현재 제품 화면에서 호출되지 않는 API를 새 목업 화면의 누락으로 계산하지 않았습니다.

## 신규 공연 준비 기능

- 아티스트 등록/수정·검색·공연 형태·연락 담당자/에이전시·자료 URL·행사 이력·재부킹.
- 부킹 보드/목록·검색·행사/상태 필터, 담당자·다음 업무/기한, 홀드 재확인·확정/취소·변경 이력.
- 실제 날짜/시간의 출연 구간 비교. 같은 소유 범위의 동일 아티스트 또는 같은 베뉴/무대 겹침. 출연 후 무대 교체·다음 행사 이동 여유를 포함하고 필요한 여유가 확보되면 연속 구간을 허용. 자정 넘김·미정 일정 표시. 리허설 점유·외부 일정 수집은 미구현.
- 프로필의 기본 자료와 행사 자료 분리, 일정 변경 후 가능 응답 초기화·재확인, 자료 제출과 운영팀 검토 분리, 행사 하나의 공유 필드만 보여주는 아티스트 응답 미리보기. 독립 외부 인증·발송·파일 업로드는 미구현.
- 행사별 출연표·자료 누락, 준비 업무 추가/수정·담당자/기한·완료/재개. 확정 부킹→비활성 게스트 링크→해당 링크 상세에서 활성화/등록 연결. 부킹 취소 시 사유·등록/입장 영향·링크 유지/중지를 선택하고 다른 확정 출연의 공용 링크를 보호.
- 확인 필요 필터·부킹 상세의 조작 가능한 항목: 후속 기한/홀드/충돌/상대 응답/자료/업무/링크/출연 결과. 각각 수정·응답·검토·업무·링크 화면으로 연결.
- 현재 베뉴에 대한 소유 범위와 관리자 접근을 모의 상태에서 검사. 실제 조직 membership·서버 권한·다중 팀 협업 보안은 새 제품 구현이 필요함.

확인할 상태: 입력 오류 · 저장 실패/오프라인 입력 유지 · 기한 지난 홀드 · 일정 충돌 · 상대 미확인 · 확정 후 재확인 · 권한별 목록 · 빈 결과.

## 검토 순서

1. 명단에서 등록·검색·중복 확인·삭제를 확인합니다. CSV는 이름 열을 선택하고 미등록 행이 남는지 확인합니다.
2. SORA로 인원을 요청하고 관리자에서 일부 인원을 승인한 뒤 SORA의 한도 증가를 확인합니다.
3. 외부 RSVP를 등록한 뒤 QR 아래 문자열을 복사해 도어에서 조회·입장 처리합니다. 외부 화면으로 돌아가 입장 후 수정·취소 제한을 확인합니다.
4. 오프라인 상태에서 체크인·워크인을 입력한 뒤 정상/충돌/거부/다른 기기 마감 상태로 전환하고 동기화 결과를 확인합니다.
5. 관리자가 행사를 종료한 뒤 입장 합계를 마감하고, 마감 리포트를 확정·CSV로 내려받습니다. 일반 명단은 행사 종료 없이 입장 합계를 마감할 수 있습니다.
6. 계정을 생성하고 초대 링크의 열기 버튼으로 비밀번호 설정을 완료합니다. 재발급·비활성화·삭제와 자기 계정 제한을 확인합니다.
7. 로그인 화면에서 재설정을 요청해 확인번호를 확인하고, 관리자에서 같은 번호와 본인 확인을 입력해 승인합니다. 로그인 미리보기로 돌아가 승인 상태 확인 후 새 비밀번호를 설정합니다.
8. 전체 관리자로 베뉴를 생성·수정·비활성화하고, 기간 통계에서 월/분기/연·이전 기간·기여자 정렬과 행사 리포트 진입을 확인합니다.

## 모의 실행 범위

- 등록·승인·입장·마감·계정·링크·베뉴의 변경은 한 탭의 메모리 상태에만 반영됩니다. 새로고침 또는 샘플 초기화로 사라집니다. 실제 API·D1·KV·인증·이메일·도메인 설정에는 연결하지 않습니다.
- QR은 샘플 코드로 실제 SVG를 생성합니다. 도어에는 현재 제품과 같은 QR 문자열 조회가 있습니다. 새로운 카메라 스캔 기능은 포함하지 않습니다.
- 오프라인·네트워크·실패·만료·결과 불일치는 상단 상태 선택으로 재현하는 목업입니다. 실제 저장소 영속성·네트워크 재접속·보안 토큰 검증의 구현이나 검증을 뜻하지 않습니다.
- 초대·재설정·등록 링크는 검토용 주소입니다. 생성 후 열기 버튼은 같은 목업 상태 안에서 흐름을 연결합니다. 다른 탭·다른 기기로 실제 인증이나 초대를 전송하는 서비스는 아닙니다.
- 언어 전환은 한국어·영어 제품 화면과 계정 선호 언어를 반영합니다. 샘플 인명·베뉴명·입력 내용과 이 기능 안내 문서의 고유 표현은 그대로 유지합니다.
- DOM 동작 확인과 브라우저 렌더링·실기기·접근성 검증은 별개입니다. 화면의 시각적 적합성과 제품 적용 여부는 이 목업을 검토한 뒤 결정합니다.
