# Authon 하단 중심 작업 화면 목업

기존 서비스의 게스트 등록·입장 처리·운영 기능을 하단 메뉴와 작업 도구로 재배치한 인터랙티브 목업입니다. 모든 이름·수치는 가상 샘플이며 API, 인증, 운영 DB에 연결되지 않습니다. 새로고침하면 샘플 상태로 초기화됩니다.

## 실행

저장소의 설치된 의존성을 사용합니다. 패키지 추가나 서비스 실행은 필요하지 않습니다.

```sh
node mockups/bottom-workspace/build.mjs --serve
```

`http://127.0.0.1:4176`에서 열거나 생성된 `dist/index.html`을 직접 엽니다. HTML에 React·스타일이 포함되어 외부 CDN 없이 사용할 수 있습니다. `--serve`를 빼면 파일만 생성합니다.

## 화면 배치

| 영역         | 배치와 목적                                                 |
| ------------ | ----------------------------------------------------------- |
| 상단         | 베뉴·운영일·행사를 지속 표시. 행사 선택은 시트에서 처리     |
| 중앙         | 현재 명단·요청·행사·통계. 넓은 화면은 명단 옆에 입장 집계   |
| 하단 첫 줄   | 역할별 주요 메뉴 3–4개. 같은 행사 범위를 유지하며 화면 전환 |
| 하단 둘째 줄 | 현재 화면의 검색·필터·등록·코드 조회·워크인 작업            |
| 바텀시트     | 게스트 등록·상세·필터·요청·링크 생성·짧은 확인 작업         |

| 사용자      | 기본 메뉴                         | 추가 화면                                        |
| ----------- | --------------------------------- | ------------------------------------------------ |
| Door 스태프 | 게스트 명단 / 입장 집계 / 내 계정 | 코드 조회, 입장 취소 확인, 작업자 이름           |
| DJ·스태프   | 내 명단 / 인원 요청 / 내 계정     | 단건·여러 명 등록, 남은 한도, 요청 결과          |
| 베뉴 관리자 | 운영 / 명단 / 행사 / 더보기       | 요청 검토, 등록 링크, 계정, 통계, 입장 집계·마감 |
| 전체 관리자 | 관리자 구성과 동일                | 더보기에 베뉴 관리 추가                          |
| 외부 등록자 | 단일 행사·초대 화면과 등록 버튼   | 담당자 다중 등록 / 본인 1명 등록·입장 코드       |

상단의 역할·모바일 폭 선택은 목업 검토 도구입니다. 실제 서비스에서 역할을 임의 전환하는 UX를 제안하는 것이 아닙니다. 공용 계정의 실제 작업자 이름은 계정 시트에 배치했습니다.

## 눌러볼 흐름

1. Door: 하단 이름 검색 → 행의 입장 버튼 → 누적 입장 반영 → 입장 완료 버튼으로 취소 확인. 코드 조회는 `DEMO01` 사용.
2. Door: 입장 집계 → 워크인 1명 추가 → 마지막 워크인 되돌리기. 게스트 체크인과 워크인을 분리하며 합계는 누적 입장입니다.
3. DJ·스태프: 등록 → 단건·여러 명 입력 → 내 명단·한도 반영. 중복 이름·한도 초과는 인라인 오류.
4. 관리자: 운영의 요청 배너 → SORA 요청 승인 → 상단 역할을 DJ·스태프로 전환해 증가한 한도 확인. 승인 뒤 새 인원 요청 가능.
5. 관리자: 더보기 → 등록 링크 → 생성·활성 전환·상세. 외부 등록 미리보기는 상단 역할 선택에서 별도로 확인.
6. 행사 선택: 9월 18일로 변경해 빈 명단 확인. 각 행사 데이터는 분리하고 돌아오면 앞선 샘플 변경을 유지.
7. 외부 등록: 본인 등록 → 이름 입력 → 완료·샘플 코드. 담당자 등록은 여러 명 입력과 등록 결과 확인.

## 상세 설계에서 이어갈 화면

이번 목업은 배치와 핵심 흐름을 검토하는 범위입니다. 로그인·최초 비밀번호 설정·재설정은 작업 화면 진입 전 독립 화면, 프로필은 계정 시트와 상세 화면으로 이어지는 구조입니다. 행사 생성·종료·보관, 마감 리포트, 계정 생성·권한·비밀번호 승인·삭제, 베뉴 생성·설정, 기간 비교 통계·다운로드는 중앙 작업 영역의 상세 화면으로 배치하며 실제 동작은 구현하지 않았습니다.

실제 QR 발급·스캔, 오프라인 큐·동기화 충돌, 서버 로딩·실패, 세션 만료, CSV 부분 성공·동명이인 확인, 링크 만료·비활성 안내, 장문 리포트는 후속 상세 설계 대상입니다. 목업의 중복 이름 차단과 마감 뒤 입력 잠금은 검토용 단순화로 실제 운영 정책 변경을 제안하지 않습니다. 계정 역할·도어 접근·베뉴·등록 소유권은 실제 구현 시 기존 서버 계약을 유지해야 합니다.

## 구조와 검증 범위

`App.tsx`는 행사별 샘플 상태와 역할·화면 전환을 소유합니다. `guests`, `door`, `admin`, `registration`은 각 작업 화면과 전용 스타일을 소유하고 `shared`는 아이콘과 네이티브 dialog 시트를 제공합니다. 앱 route나 배포 파일에 목업을 연결하지 않았습니다.

반응형 container query로 모바일에서 한 열, 넓은 화면에서 명단과 집계를 나눕니다. 네이티브 dialog의 포커스 제한·Escape·닫은 뒤 포커스 복귀, 입력 label, 상태 알림, reduced motion을 포함합니다. 브라우저 시각·기기·키보드 검증을 수행했다는 의미는 아닙니다.
