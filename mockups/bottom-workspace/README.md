# Authon 전체 기능 목업

기존 서비스의 사용자 화면과 업무 흐름을 하단 메뉴 중심으로 재구성한 인터랙티브 목업입니다. 아티스트·부킹·일정·행사 준비부터 게스트 등록, 도어, 운영 관리와 통계까지 샘플 상태로 연결됩니다. [기능별 대응표](COVERAGE.md)에서 현재 제품의 근거와 목업 진입 경로를 확인할 수 있습니다.

## 열기

```sh
node mockups/bottom-workspace/build.mjs --serve
```

`http://127.0.0.1:4176`에서 열거나 생성된 `dist/index.html`을 직접 엽니다. HTML에 코드·스타일·QR 생성기를 포함하며 외부 CDN 없이 동작합니다. `--serve`를 빼면 파일만 생성합니다. 저장소에 설치된 의존성을 사용합니다.

## 새 공연 준비 흐름

`http://127.0.0.1:4176/#planning/bookings`에서 부킹 화면을 바로 엽니다. 아티스트·일정·준비 업무는 하단 메뉴 또는 **전체 → 공연 준비**에서 연결됩니다. 기존 명단·도어·행사 메뉴도 유지합니다.

1. **아티스트:** 이름·공연 형태·담당자·에이전시·자료 링크·내부 메모를 등록하거나 수정합니다. 상세에서 기존 출연 이력을 보고 **이 아티스트 부킹**을 누릅니다.
2. **부킹:** 행사·담당자·다음 할 일·기한을 정하고 문의→조율/홀드→확정 흐름을 진행합니다. 보드/목록과 검색·상태·행사 필터를 사용할 수 있습니다. 시작과 종료는 각각 날짜까지 지정합니다.
3. **일정 조율:** MILO와 WAVE FORM의 샘플은 같은 무대에서 겹칩니다. 출연 후 무대 교체 시간·다음 행사 이동 시간을 0~240분으로 지정할 수 있습니다. 같은 베뉴의 다른 행사라도 같은 무대가 겹치면 표시합니다. 확정된 출연과 겹치거나 상대 가능 여부가 미확인이면 신규 확정을 막으며, 지난 홀드는 재협의 대상으로 남깁니다.
4. **아티스트 확인:** 부킹 상세의 **아티스트 화면 미리보기**에서 해당 행사 시간표·자료만 봅니다. 가능 여부와 기술자료 URL을 제출하거나 확정 일정을 확인합니다. 시간·장소·교체/이동 시간을 수정하면 이전 가능 응답을 초기화합니다. 기존 확정 부킹은 자리를 유지하며 재확인이 필요한 상태로 표시합니다. 자료 변경 시 아티스트 확인과 운영팀 자료 검토를 모두 다시 받습니다. 실제 초대·발송·외부 계정 로그인은 수행하지 않습니다.
5. **공유 일정:** 주간/목록과 날짜·행사·아티스트 필터로 출연표를 확인합니다. 자정을 넘는 출연은 실제 해당 날짜에 표시합니다. 일정이 미정인 부킹은 별도 목록에 남습니다.
6. **행사 준비:** 도착·사운드체크·출연 시간, 자료 누락·아티스트 확인·운영팀 자료 검토를 따로 봅니다. 자료 검토에서 현재 행사 자료를 확인하고 완료로 기록합니다. 준비 업무는 내용·담당자·기한을 수정하거나 완료/다시 열기로 관리합니다.
7. **현장 연결:** 확정된 부킹에서 한도를 정해 비활성 게스트 링크를 준비합니다. **연결된 게스트 링크**는 해당 링크 상세를 바로 열며 활성화·외부 등록으로 이어집니다. 부킹 상세에 연결 링크의 등록·입장 인원을 표시합니다. 취소할 때 사유와 링크 상태 유지/추가 등록 중지를 선택하며, 기존 게스트와 입장 기록은 보존합니다. 같은 링크를 사용하는 다른 확정 부킹이 있으면 중지를 막습니다.

**확인 필요** 필터와 부킹 상세에서 당일/지난 후속 기한, 홀드, 충돌, 상대 조정 요청, 자료 검토, 남은 업무, 링크 상태를 모아 보고 각 조작 화면으로 이동합니다.

조사 근거와 적용·후속 범위는 [부킹 파이프라인 검토](PIPELINE.md)에 정리했습니다.

자료 URL은 `example.com`의 가상 주소입니다. 업로드·자료 내용·외부 공유의 실제 동작을 의미하지 않습니다. 새 기능의 시간 비교는 KST의 출연 시작/종료 구간을 기준으로 하며, 다른 베뉴/조직의 일정 수집, 리허설·사운드체크의 점유 구간과 외부 캘린더 동기화는 후속 범위입니다. 교체·이동 시간은 담당자가 직접 입력하며 실제 이동 경로를 계산하지 않습니다.

## 검토 도구

- **역할 미리보기:** 관리자, SORA·MILO, 공용 운영팀, Door, 전체 관리자, 로그인과 외부 등록 화면을 전환합니다.
- **기능 목록:** 기존 16개와 신규 공연 준비 4개 기능 영역과 세부 항목을 확인하고 해당 목업을 바로 엽니다. 마지막 버튼으로 샘플 데이터를 초기화합니다.
- **검토 설정 → 목업 상태:** 로딩, 조회·저장 실패, 세션 만료, 오프라인·충돌, 링크 만료, 저장소 불가, QR 실패와 리포트 불일치 등을 해당 화면에서 확인합니다. 정상으로 되돌려 복구 흐름을 이어갑니다.
- **검토 설정 → KO / EN:** 화면 언어를 바꿉니다. 계정의 기본 언어는 프로필에서도 저장할 수 있습니다.
- **검토 설정 → 화면 크기:** 자동 / 모바일 390px / 태블릿 834px / 데스크탑 1280px을 전환합니다. 실제 창이 더 좁으면 가용 폭에 맞춥니다. 기본은 자동입니다.

목업의 기준 운영일은 **2026-09-12**, 샘플 시각은 다음 날 00:18 KST입니다. 과거·미래 날짜와 일반 명단은 행사 선택에서 확인합니다. 새로고침하면 모든 변경이 초기화됩니다.

로그인 예시는 `sora@example.com` / `DemoPass123`입니다. 미설정 계정의 코드 흐름은 `invited@example.com` / `MOCK-INVITED`로 확인합니다. 모두 목업 전용 가상 값입니다. 재설정 승인용 4자리 확인번호는 사용자 요청 화면에서 확인한 뒤 관리자 화면에 입력합니다.

## 화면 크기와 작업 배치

### 데스크톱 사이드바 / 상단 메뉴 비교

`http://127.0.0.1:4176/?door-compare=1&workspace-layout=sidebar#workspace/door`를 열면 Door 계정과 합성 명단 20명으로 시작합니다. **A · 좌측 사이드바 / B · 상단 메뉴**로 같은 명단을 비교합니다. `workspace-layout=top`은 상단 메뉴로 시작합니다.

- **사이드바:** 왼쪽 190px에 역할별 메뉴를 세로로 배치하고 계정을 아래에 둡니다. 관리자 역할은 접근 가능한 추가 화면도 직접 표시합니다.
- **상단 메뉴:** 로고·주요 메뉴·계정을 상단 한 줄에 둡니다. 그 외 화면은 전체 메뉴에서 열며 선택한 화면은 주요 메뉴에 표시합니다.
- 두 안의 코드 조회·워크인 등 현재 화면 작업은 본문 헤더에 있습니다. 데스크톱 명단은 이름·등록 담당자·입장 상태를 한 행에 표시합니다. 입력자와 정확한 입장 시각은 상세에서 확인합니다.
- 실제 미리보기 프레임이 1000px 미만이면 기존 하단 pill 두 줄을 사용합니다. **검토 설정 → 화면 크기**에서 좁은 크기를 비교할 수 있습니다. 자동 크기는 최대 1440px입니다.
- 메뉴형 전환은 같은 화면·샘플·검색·필터·입장 결과·열린 상세를 유지합니다. 화면 크기가 바뀌어도 열린 입력 폼은 유지합니다. 이 비교는 기존 명단 A/B와 별도 주소입니다.

### Door 명단 A/B 비교

`http://127.0.0.1:4176/?door-compare=1&door-layout=columns#workspace/door`를 열면 Door 계정과 합성 명단 20명으로 시작합니다. 위쪽 **A · 열 정렬 / B · 이름 중심** 버튼으로 전환합니다. **검토 설정 → 화면 크기**에서 모바일·태블릿·데스크탑을 비교합니다.

- **A:** 기존 명단 열과 밀도, 좁은 화면의 검색 열기 동작을 유지합니다.
- **B:** 이름 아래에 담당자·입력자를 묶고, 입장 버튼 아래에 시각을 표시합니다. 검색창은 모든 크기에서 항상 표시합니다. 넓은 화면에서 이름을 누르면 기존 선택 상세 패널이 열립니다.
- A/B는 같은 상태를 공유합니다. 전환 시 검색어·필터·선택 상세·입장 결과·오프라인 대기를 초기화하지 않습니다. 실제 버튼·검색을 조작할 수 있는 메모리 목업이며 제품 API·DB와 연결하지 않습니다.
- `door-compare=1` 없는 기존 주소는 원래 계정·샘플로 시작합니다. 비교 중 새로고침하면 20명 샘플로 초기화됩니다. `door-layout=identity` 주소는 B로 시작합니다.

기본 하단 메뉴형은 모든 크기에서 같은 상단 범위와 하단 독립 pill 두 줄을 사용합니다. 태블릿·데스크탑의 목록은 본문 폭을 사용해 비교할 정보를 열로 펼칩니다. 명단은 이름과 입장 버튼을 나란히 두고 등록 담당자·입력자·입장 시각을 표시합니다. 계정은 이메일·역할·유형, 링크는 종류·등록 수·만료, 요청은 인원·사유, 행사는 날짜·등록 수·수용 인원, 베뉴는 도메인·운영 시간을 정렬합니다. 좁아지면 보조 정보를 이름 아래로 모으며 같은 버튼과 상세 동작을 유지합니다.

제목·행사 범위·본문은 같은 작업 영역에 맞춥니다. 계정 검색과 링크 필터는 넓은 화면에서 한 줄로 배치합니다. 부킹은 아티스트·행사, 출연 일정, 후속 업무를 정렬하고 아티스트 디렉터리·일정·통계는 기존의 넓은 본문을 사용합니다. 로그인·프로필처럼 하나의 폼을 작성하는 화면은 제목과 폼을 같은 폭으로 중앙에 둡니다.

- **선택 상세:** 실제 작업 영역이 980px 이상이고 상세 높이가 충분할 때 360px 옆 패널로 엽니다. 선택 전에는 목록 전체를 사용합니다. Door 체크인은 행에서 바로 처리하며 상세를 자동으로 열지 않습니다.
- **명단 검색과 밀도:** 본문이 700px 이상이면 검색창을 항상 표시합니다. 좁은 화면은 검색 버튼으로 펼치며, 크기를 바꿔도 입력 중인 검색어와 초점을 유지합니다. 넓은 명단·관리 목록은 행 여백을 줄이고 조작 영역은 44px 이상 유지합니다.
- **게스트 상세:** 입장 처리·취소를 첫 조작으로 두고, 등록 담당자·상태·입장 시각을 묶습니다. 본인 RSVP의 QR은 펼쳐서 확인하며, QR을 스크롤해도 처리 버튼은 상단에 남습니다. 삭제는 별도 보조 조작입니다. 성공 알림은 전체 화면에서 한 번 표시하고 상세에는 처리 오류를 유지합니다.
- **편집·확인:** 부킹과 CSV 등 긴 편집은 최대 800px 모달을 사용합니다. 승인·계정 상세에서 입력값을 바꾸면 작성 보호가 걸리고, 원래 값으로 돌리면 조회 상태로 돌아갑니다. 삭제·종료 확인은 모달로 유지합니다.
- **크기 변경:** 같은 폼 요소를 유지해 선택·입력·오류·초점을 보존합니다. 좁거나 낮은 화면에서는 상세를 모달 시트로 표시합니다.
- **넓은 본문:** 주간 일정은 날짜별 열, 준비 화면은 출연표와 업무·자료, 입장 집계는 입력과 동기화 기록, 통계·리포트는 차트와 결과를 병행합니다. 로그인·프로필·개인 RSVP는 읽기 편한 폼 폭을 유지합니다.

반응형 상태 회귀는 목업을 빌드한 뒤 `node --test mockups/bottom-workspace/workspace/responsive.test.mjs`로 확인합니다. DOM 검사는 실제 터치 기기나 소프트 키보드 검증을 대신하지 않습니다.

## 작업 화면과 사용성

- 부킹 요약은 한 줄로 표시하며, 검색 아이콘으로 검색란을 펼칩니다. 검색어가 있을 때 Escape는 검색어를 지우고, 다시 누르면 검색란을 닫습니다. 행사·상태 필터는 유지합니다. 일정의 추가 필터는 **필터** 버튼으로 펼칩니다.
- 화면 제목과 선택된 메뉴의 이름을 맞추고, 베뉴·운영일·행사 선택과 운영 상태를 그 아래 한 줄에 모읍니다. 긴 행사명은 말줄임하고 선택 창에서 전체 이름을 확인합니다. 선택된 pill은 밝은 배경과 진한 글자로 구분합니다.
- 공연 준비 화면의 중복 상단 탭과 관리 목록의 중복 생성 버튼을 정리했습니다. 생성 작업은 하단에 모으고, 목록의 검색·날짜·필터는 간격을 둬 구분합니다. 부킹의 출연 시간은 강조하며 같은 날의 종료 날짜는 반복하지 않습니다.
- 일정은 오늘과 선택 날짜를 각각 구분합니다. 좁은 화면에서는 보기·필터가 줄바꿈하고 주간 날짜의 조작 폭을 확보합니다. 긴 하단 작업 이름은 한 줄을 유지하며, 공간이 부족하면 해당 pill 줄을 가로로 탐색합니다.
- 하단 주요 메뉴는 텍스트 중심의 짧은 pill로 표시합니다. 관리자 기본 메뉴는 부킹·일정·명단·도어·행사이며, 좁은 폭에서는 네 개를 표시합니다. 다른 화면을 선택하면 마지막 자리에 현재 메뉴를 표시합니다. 메뉴 양끝의 표시는 긴 번역 등으로 가로 탐색이 필요할 때 나타나며, 현재 메뉴와 키보드로 이동한 메뉴는 보이는 영역으로 들어옵니다.
- 작은 **전체** 버튼과 관리자 대기 요청 수는 항상 보입니다. **전체 메뉴**는 검색란 아래에 업무별 pill을 배치하고, 넓은 화면에서는 분류를 두 열로 정렬합니다. 메뉴를 선택하면 시트가 닫히고 현재 메뉴로 초점이 이동하며, 닫기·Escape는 전체 버튼으로 돌아갑니다.
- 새 화면·행사·역할로 전환하면 본문 맨 위에서 시작하고, 같은 목록의 상세를 닫으면 원래 위치를 유지합니다. 화면 이동은 `#planning/...`, `#workspace/...`, `#external/...`, `#auth/...` 주소와 동기화됩니다. 목업 화면 사이의 브라우저 뒤로가기는 열린 시트를 먼저 닫으며 작성 내용 보호를 따릅니다.
- 부킹의 확인 필요 항목은 해당 자료·담당자·후속 기한·출연 시작·홀드 기한 입력으로 바로 연결합니다. 누락 자료 영역은 펼쳐지고 첫 누락 입력에 포커스가 갑니다. 지난 기한과 오늘 기한을 구별하며 링크 만료는 KST로 표시합니다.

제공된 React 코드와 이미지의 검정·무채색·초록·파랑을 기본으로 유지합니다. 배경 `#000000`, 시트 `#141414`, 버튼 `#1c1c1c`, 일반 선택 상태 `#2a2a2a`, 보조 글자 `#8e8e93`, 초록 `#10b981`, 파랑 `#3b82f6`입니다. 현재 메뉴는 인지하기 쉽게 배경 `#e7e7e7`과 글자 `#111111`을 사용하며, 초록색 주요 버튼에는 짙은 글자를 사용합니다.

- 화면은 기능명과 조작 항목으로 구성합니다. 소개성 제목·사용법 문단·버튼을 다시 설명하는 문장은 넣지 않습니다. 단위·시간대·입력 한도는 해당 항목에 표시하고, 오류·현재 상태·변경 영향은 필요한 시점에 짧게 안내합니다.
- 명단·도어·입장 집계는 행사와 운영 상태를, 계정·링크·통계는 전체 계정/행사 범위를 화면 위에 표시합니다. 명단과 도어는 전체·미입장·입장 완료 필터에 인원을 함께 표시하고 별도 요약과 목록 제목의 중복을 줄입니다. 개인 역할의 내 등록·남은 한도는 작은 요약으로 유지합니다.
- 인원 요청은 상단에 한도·남은 인원·승인 대기 상태를 표시하고, 요청 작성은 하단 버튼에서 시작합니다. 계정·링크·일정의 필터는 선택값과 연결된 접근성 라벨을 유지하면서 반복 문구를 줄입니다. 통계의 날짜와 이전·다음 이동은 같은 줄에 표시합니다.
- 하단은 레퍼런스의 독립 pill 두 줄을 유지합니다. 윗줄은 화면별 작업 버튼, 맨 아래는 항상 유지되는 텍스트 탐색 메뉴입니다. 작업이 없으면 윗줄만 사라지고 탐색 메뉴의 하단 위치는 유지합니다. 마크업과 키보드 이동도 같은 순서이며 각 줄의 가로 스크롤과 요청 건수 표시를 유지합니다.
- 필터·입력 시트·미리보기 설정·외부 등록의 단일 선택 드롭다운은 텍스트 시작·화살표 오른쪽·텍스트와 화살표 사이에 같은 10px 여백을 사용합니다. 12px 화살표를 포함한 오른쪽 예약 공간은 32px이며 실제 선택·키보드 조작은 기본 select를 유지합니다.
- 폼의 기본 입력 높이는 46px, 안쪽 여백과 모서리는 10px이며 입력 글자는 16px를 유지합니다. 입력 묶음 간격은 16px, 라벨과 입력 간격은 6px입니다. 선택·여러 줄 입력도 필수 표시를 통일하고 오류·초점·비활성 상태를 구분합니다.
- 관리 목록과 부킹·일정·준비 업무의 행 간격, 상태와 보조 정보의 글자 크기를 같은 기준으로 맞췄습니다. 상세의 항목명 열은 짧게 두고 값이 줄바꿈할 공간을 확보합니다. 통계의 주요 숫자는 20px와 고정 숫자 폭을 사용하고, 집계·리포트·프로필 요약은 18px로 표시합니다. 여러 줄 라벨에서도 숫자의 기준선이 맞으며 좁은 화면은 두 열로 정리합니다.
- 확인 창과 빈 화면의 중복 여백을 줄였습니다. 긴 상태 문구와 버튼은 폭에 맞춰 줄바꿈하며 작은 필터 해제·확인 조작은 44px 이상의 영역을 확보합니다. 펼침 메뉴는 같은 화살표와 초점 표시를 사용하고 마우스 hover 피드백은 정밀 포인터에서만 표시합니다.
- 하단에 옅게 이어지는 배경 위로 pill을 배치합니다. 하단 영역의 실제 높이에 맞춰 목록 끝의 여백을 확보하고, 키보드 포커스 테두리를 위한 여백을 둡니다. 이 구조를 유지한 상태에서 검색·입력·복구 동작을 개선합니다.
- 하단의 비동작 손잡이를 제거하고 불필요한 여백을 줄였습니다. 하단 두 줄은 버튼 내용에 맞는 폭으로 중앙에 모으며 `전체`를 탐색 메뉴 바로 옆에 둡니다. 각 작업 버튼을 균등하게 늘리지 않으며, 공개 등록·로그인 화면에는 하단 메뉴용 여백을 남기지 않습니다. 외부 RSVP의 주 행동은 전체 폭 버튼으로 표시합니다.
- 명단의 상태 필터와 검색·정렬 아이콘은 한 줄에 배치합니다. 검색 아이콘을 누르면 필터 아래 이름·담당자 검색창이 열립니다. 닫으면 검색어를 해제하고, Escape는 검색어 지우기 → 닫기 순서로 동작합니다. 검색과 필터는 스크롤 중에도 사용할 수 있습니다.
- 전체·미입장·입장 완료 필터와 담당자·정렬 등 적용한 조건을 표시하고 개별 해제할 수 있습니다. 검색 결과가 없으면 검색·필터 초기화로 돌아갑니다. 코드 조회에 실패하면 이름 검색창으로 바로 이어집니다.
- 본문과 시트는 화면 너비 안에서 세로로 스크롤하며 긴 이름·폼·QR의 너비를 제한합니다. 넓은 통계 표는 표 자체의 가로 스크롤로 열을 확인할 수 있습니다.
- 전체 메뉴는 공연 준비 / 현장 운영 / 행사와 기록 / 계정과 설정으로 나눕니다. 화면에는 기능명·대기 건수만 표시하며, 짧은 메뉴명과 정식 기능명·관련 업무 키워드로 검색할 수 있습니다. 역할별 접근 범위를 유지합니다.
- 단건·다중 등록 입력은 모드를 전환해도 각각 남아 있습니다. 중복 포함 승인은 모드를 전환하면 다시 확인합니다. CSV 안내는 실제로 불러오기 전의 상태를 구별합니다.
- 등록·계정·행사·링크·베뉴·RSVP 등 작성 시트에서 입력 후 닫기 또는 Escape를 누르면 계속 작성하거나 버릴 수 있습니다. 필터·조회 시트는 바로 닫힙니다. 입력 보존은 열린 시트 안에서만 동작하며 새로고침·탭 종료 후 복원은 제공하지 않습니다.
- 시트 제목·닫기와 폼 제출 영역을 유지하고, 모바일 가시 영역 변화에 맞춰 시트 높이를 조절합니다. 넓은 화면에서는 시트 폭을 제한해 긴 입력란을 줄입니다.
- 체크인 성공은 게스트 이름과 함께 알립니다. 실패 시 상세 화면과 재시도 버튼을 유지합니다. 입력 오류는 이름 필드에 연결합니다.

DOM 검증은 상태 전환과 입력 보존 등의 동작을 확인하는 범위이며, 실제 브라우저 렌더링과 실기기 동작은 별도로 구분합니다.

## 구현 경계

역할별 메뉴·직접 URL·저장 동작과 외부 링크의 허용 범위는 [접근 권한표](ACCESS.md)에 정리했습니다. 역할 미리보기의 **개인 스태프**, **운영팀**(공용·도어 허용), **등록 전용 운영팀**으로 계정 유형에 따른 차이를 확인할 수 있습니다. **Door 01**은 개인 도어 스태프 계정입니다.

### 베뉴 구성별 검토

상단 **검토 설정 → 베뉴 구성**에서 기본 2개·1개·없음·모두 비활성·행사 없음·보관 행사만 있는 상태를 선택할 수 있습니다. 구성을 바꾸면 샘플 데이터가 초기화됩니다. 역할 미리보기의 **베뉴 미지정 DJ**로 소속 없는 계정도 확인합니다.

- **일반 계정:** 현재 제품과 같이 한 베뉴에 소속됩니다. 베뉴는 고정 이름으로 표시하고 운영일·행사만 선택합니다. 다른 베뉴로 대체하지 않습니다.
- **전체 관리자:** 접근 가능한 활성 베뉴가 2개 이상이면 베뉴 선택을 표시하고, 1개면 고정 이름만 표시합니다. 베뉴 전환은 운영일을 유지하고 해당 베뉴·날짜의 명단만 선택합니다.
- **베뉴 없음:** 운영 데이터와 작업 버튼을 숨깁니다. 전체 관리자는 첫 베뉴 생성·비활성 베뉴 관리로, 일반 계정은 관리자 연결 안내로 이어집니다. 프로필은 계속 열 수 있습니다.
- **행사 없음/보관 행사만 있음:** 다른 날짜나 다른 베뉴의 행사를 가져오지 않습니다. 일반 명단으로 시작하거나 관리자라면 새 행사를 만들 수 있습니다. 행사 선택이 필요 없는 계정·링크·통계 화면은 계속 사용할 수 있습니다.

일반 사용자의 복수 베뉴 membership은 현재 제품·목업 모델에 없습니다. ‘기본 2개’는 샘플에 존재하는 베뉴 수이며, 실제로 표시되는 선택지는 계정 권한을 따릅니다.

### 기능 대응

기존 제품과의 기능 대응을 보완했습니다.

- 관리자 숫자 키: **1 명단 / 2 링크 생성 / 3 계정 생성 / 4 통계 / 5 베뉴(전체 관리자)**. 입력란·시트·조합 키·한글 조합 중에는 동작하지 않습니다.
- 링크 생성: 날짜를 직접 지정한 뒤 일반 명단 또는 같은 날짜의 행사를 선택합니다. 새 날짜의 일반 명단은 자동으로 준비되며 같은 베뉴·날짜에서 재사용합니다. 행사명은 필수이고, 생성 결과와 외부 등록에 선택 날짜를 표시합니다. 목록의 DJ 이름순 정렬도 반영합니다.
- 통계: `#workspace/analytics?grain=quarter&period=2026-Q3&compare=previous`처럼 기간을 주소에 저장합니다. 뒤로가기·앞으로가기·새로고침으로 해당 기간을 복원합니다. 잘못된 기간 표기는 유효한 기본 기간으로 복구하며, 미래 기간은 조회 불가 상태를 표시합니다.

이 폴더는 제품 route에 연결되지 않은 독립 목업입니다. `data/MockData.tsx`가 가상 데이터와 지연·실패 상태를 소유하고, 각 capability 폴더가 화면·입력·확인 동작을 소유합니다. 게스트/CSV 파싱, 계정 권한, 행사 상태 전환과 통계 기간·집계에는 기존의 순수 함수를 재사용합니다.

새 `planning/` capability는 화면별 컴포넌트와 상태 전이·시간 충돌 규칙을 분리하고, 데이터는 기존 `MockData`의 단일 메모리 상태에 저장합니다. 목업에서는 현재 베뉴를 소유 범위로 삼습니다. 실제 운영팀 membership·여러 베뉴의 공동 권한·외부 초대 보안은 제품 구현이 필요합니다. 아티스트 미리보기는 같은 로컬 목업 안의 시점 전환이며 독립 인증된 외부 세션이 아닙니다.

결제·비용·매출·정산은 이번 목업에 추가하지 않습니다. API·DB·실제 인증·메일·배포·도메인 변경을 수행하지 않습니다. 공유 링크, 영속 저장과 네트워크 오류는 모의 실행 범위를 따르며 상세 내용은 [대응표](COVERAGE.md)에 명시했습니다. 제품 적용과 실제 브라우저·기기 검증은 별도 단계입니다.
