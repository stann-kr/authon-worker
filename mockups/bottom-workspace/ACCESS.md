# 목업 접근 권한

기존 제품의 `lib/users/policy.ts`를 기준으로 메뉴·직접 경로·저장 시점의 역할을 확인합니다. 베뉴 소유 범위와 게스트·계정·요청·외부 링크 대상도 별도로 검사합니다.

| 계정 | 내부 명단 | 체크인·워크인 | 추가 인원 요청 | 행사·부킹·링크·통계 | 계정·승인 | 베뉴 관리 |
| --- | --- | --- | --- | --- | --- | --- |
| 전체 관리자 | 선택 베뉴 전체 | 가능 | 승인·거절 | 가능 | 관리 가능 | 가능 |
| 베뉴 관리자 | 소속 베뉴 전체 | 가능 | 승인·거절 | 가능 | 소속 하위 계정 | 불가 |
| 도어 스태프 | 내 명단 / 도어에서 베뉴 전체 | 가능 | 불가 | 불가 | 불가 | 불가 |
| 개인 스태프·DJ | 본인 내부 명단 | 불가 | 유한 한도일 때 가능 | 불가 | 불가 | 불가 |
| 공용 스태프·도어 허용 | 내 명단 / 도어에서 베뉴 전체 | 가능 | 불가 | 불가 | 불가 | 불가 |
| 공용 스태프·등록 전용 | 본인 내부 명단 | 불가 | 불가 | 불가 | 불가 | 불가 |

- 도어 권한은 마감 합계·리포트 확정 권한을 포함하지 않습니다. 확정은 관리자만 할 수 있습니다.
- 내부 등록은 계정 한도를 따르며 공용 계정은 현재 입력자 이름이 필요합니다. 개인 계정에 도어 플래그만 붙여서는 도어 권한이 생기지 않습니다.
- 공용 계정의 역할은 스태프만 허용합니다. 개인 계정은 별도 도어 플래그를 가질 수 없으며 도어 스태프 역할 자체로 도어에 접근합니다.
- 관리 화면에서 자기 계정을 변경하거나, 베뉴 관리자가 동급·최고 관리자 또는 다른 베뉴 계정을 관리할 수 없습니다. 전체 관리자도 새 최고 관리자 생성·역할 승격은 제공하지 않습니다. 마지막 활성 최고 관리자 보호를 유지합니다.
- 재설정 승인은 관리 가능한 활성 대상·동일 요청의 확인번호·본인 확인·대기 상태를 저장 시점에 다시 확인합니다. 본인 요청은 다른 관리자가 처리합니다.
- 모든 활성 계정은 자기 프로필을 사용할 수 있습니다. 소속 베뉴가 없거나 비활성이어도 다른 베뉴로 대체하지 않습니다. 일반 계정의 복수 베뉴 소속은 현재 모델에 없습니다.

## 외부 접근

| 진입 | 허용 범위 |
| --- | --- |
| 외부 담당자 링크 | 해당 링크의 등록·명단·입장 전 삭제 |
| 본인 RSVP 링크 | 같은 브라우저의 본인 등록·수정·취소·QR |
| 로그인·설정·재설정 | 해당 모의 계정·일회용 코드·요청 확인 흐름 |
| 아티스트 화면 미리보기 | 관리자 안에서 선택한 부킹의 공유 필드·모의 응답 |

외부 링크의 사용 방식·활성/만료·베뉴/행사·마감 여부를 화면과 저장 시점에 확인합니다. 본인 RSVP에서 다른 참가자 명단을 표시하지 않으며 입장 후 수정·취소를 막습니다.

## 구현 경계

이 문서는 **독립 목업의 동작 계약**입니다. 모든 샘플 데이터와 검토용 역할 전환이 브라우저에 포함되어 있으므로 실제 인증·개인정보 보호의 보안 경계가 아닙니다. 실제 서비스의 세션·서버 권한·DB 조회·외부 링크 토큰·다중 기기 영속성은 연결하지 않습니다. 아티스트 응답도 독립 인증된 외부 계정이 아닙니다.

`data/access.ts`가 공통 접근을, `accounts/policy.ts`가 계정 대상·권한 부여를, `registration/access.ts`가 외부 링크의 쓰기 가능 여부를 소유합니다. 기존 제품의 실제 운영 보안 검증은 별도입니다.
